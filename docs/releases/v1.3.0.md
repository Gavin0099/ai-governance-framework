# v1.3.0

Release candidate note prepared 2026-07-31. This candidate adds the F-7
response-envelope synchronization boundary and preserves the distinction
between local release-facing readiness and a published GitHub Release or tag.

## Highlights

- F-7 managed consumer instruction surfaces now carry the compact response
  policy summary for contract v0.7.
- F-7 checks explicit response-envelope version markers across `AGENTS.md`,
  Copilot instructions, and the reference contract heading.
- A legacy marker keeps existing repo text, adds the current managed policy,
  reports `response_envelope_surface: conflict`, and prevents
  `full_update_completed`.
- Focused regression coverage protects legacy conflicts and ignores historical
  version notes below a current canonical contract heading.

## Supported AI Adapter Surfaces

- Claude Code
- Codex
- Gemini

Adapter presence does not prove identical consumer wiring or enforcement
coverage. Actual capability remains bounded by the repository role, hooks,
contracts, and evidence available in that repository.

## Known Limits

- This remains a bounded prototype and audit framework, not a security boundary
  or complete policy engine.
- The response-envelope compatibility check detects explicit version markers;
  it does not infer arbitrary prose contradictions in unmanaged instructions.
- Copy-based consumers remain audit/reporting surfaces and do not gain automatic
  full-update execution from this change.
- This candidate does not prove consumer-repository adoption, fleet
  synchronization, clean-VM behavior, or domain correctness.
- Release-facing files, CI readers, and checklists do not prove that a GitHub
  Release or `v1.3.0` tag has been published.
